# Project Plan: 20.04.2026 - Bookingkit Integration
**Objective:** Replace the internal booking system with a full Bookingkit integration on the new Next.js website.

## 1. Architectural Adjustments
*   **Ditch Stripe:** Remove or disable all Stripe-related routes (`/api/checkout`, `/api/webhooks/stripe`) and client-side logic.
*   **Supabase Role:** Supabase will no longer handle real-time bookings (since Bookingkit does this). We will keep it only for:
    *   Future-proofing (if we want to move away from Bookingkit later).
    *   Managing static content (FAQ, Team, Info pages) if needed.
    *   *Note:* Since the live DB is disabled, we will use **Local Mock Data** for all UI elements that previously pulled from Supabase.

## 2. Integration Strategy
Instead of one big widget, we will create a dedicated `BookingService` that maps our Next.js pages to specific Bookingkit Widget IDs.

### **Tasks:**
1.  **Cleanup:** 
    *   Disable the `BookingWizard` component (the custom multi-step form).
    *   Remove Stripe references from `package.json` and `lib/`.
2.  **Widget Refinement:** 
    *   Enhance `BookingkitWidget.tsx` to handle responsive height and loading states.
3.  **Page Mapping:** Create/Update pages to host the widgets:
    *   `/booking`: General list (The "Alle Erlebnisse" widget).
    *   `/kurse/windsurf`: Windsurf-specific widget.
    *   `/kurse/sup`: SUP-specific widget.
    *   `/kurse/longboard`: Longboard-specific widget.
4.  **Static Data Fallback:** 
    *   Update `lib/db/queries.ts` to return mock data so the site looks "alive" during development without a live Supabase connection.

## 3. Migration Preparation
*   Identify all routes on the old IONOS/WordPress site and ensure they have a corresponding page in the new Next.js app.
*   Setup SEO redirects strategy.
